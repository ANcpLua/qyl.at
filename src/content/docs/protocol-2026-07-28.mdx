## SDK v2

The server is built on the MCP TypeScript SDK v2 (`@modelcontextprotocol/server`) and serves protocol revision `2026-07-28`. Streamable HTTP at `https://mcp.qyl.at/mcp` and stdio from `qyl-mcp-server --stdio` create every server instance from the same factory, so both transports expose the same tools and skill; only the hosted endpoint adds OAuth and Events. The hosted HTTP server is stateless: Bun serves the SDK's web-standard handler directly.

## Modern requests

`server/discover` returns the server's identity, instructions and capabilities: tools, the resources that carry the skill files, `extensions["io.modelcontextprotocol/skills"]`, and on the hosted endpoint `events`. Requests carry the revision and client capabilities in the reserved `_meta` envelope, and `clientInfo` is optional. Responses carry the server identity under `_meta["io.modelcontextprotocol/serverInfo"]`. `server/discover`, `tools/list`, `resources/list` and `resources/templates/list` carry public cache hints of five minutes.

## 2025-era clients

The hosted handler keeps the SDK's stateless fallback for clients that open with `initialize`: each such request is answered by a fresh server instance with the same tools, authorization and scope checks, and the 2025 session operations `GET` and `DELETE` answer `405`. Over stdio, the opening exchange selects the revision for that connection.

## What the server does not use

The server registers no prompts, no resource templates and no UI resources, and it sends no sampling or elicitation requests. Its resources are the skill files.

## Reproducible dependencies

The server's package manifest in the [qyl repository](https://github.com/ANcpLua/qyl) pins exact SDK and dependency versions, with one lockfile. Dependency pins and protocol negotiation are separate settings.

See the upstream [2026-07-28 support guide](https://ts.sdk.modelcontextprotocol.io/v2/migration/support-2026-07-28) for the SDK's entry points and migration behavior.
