## SDK v2, both protocol eras

qyl.mcp uses the TypeScript SDK v2 packages. Its serving entry points support `2026-07-28` and the SDK's supported 2025 revisions. Hosted requests use the same authorization checks and tool handlers through either path.

## HTTP and stdio

The hosted HTTP server uses `createMcpHandler(factory)` with its default stateless compatibility behavior. Bun serves the Web Standard handler directly. Both eras share one endpoint and server factory.

The stdio entry uses `serveStdio(factory)`. The opening exchange selects the protocol era for that connection. A 2025 `initialize` opening is supported.

## Client negotiation

The workbench explicitly configures `versionNegotiation: { mode: "auto" }`: try modern discovery, then use the SDK's 2025 fallback when appropriate. It records the revision actually negotiated. An SDK Client without this option still defaults to the 2025 handshake. Exact protocol pins remain in conformance tests for a particular era.

## Modern requests and Events

Modern discovery uses `server/discover`. Requests carry revision and capabilities in the reserved `_meta` envelope; `clientInfo` is optional. The SDK supplies server identity through `_meta["io.modelcontextprotocol/serverInfo"]` on responses.

ChatGPT Events require `2026-07-28` and configured subscription storage. Ordinary tools remain available through both protocol eras.

## Reproducible dependencies

The [server](https://github.com/ANcpLua/qyl.mcp/blob/main/server/package.json) and [workbench](https://github.com/ANcpLua/qyl.mcp/blob/main/workbench/package.json) manifests pin exact package versions, with one lockfile. Dependency pins and protocol negotiation are separate settings.

See the upstream [2026-07-28 support guide](https://ts.sdk.modelcontextprotocol.io/v2/migration/support-2026-07-28) for the SDK's entry points and migration behavior.
