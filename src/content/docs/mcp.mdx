## Endpoint

```text
https://mcp.qyl.at/mcp
```

The hosted server answers for the Collector project your account is authorized for on `api.qyl.at`. Besides `/mcp` it serves `/healthz` and the OAuth discovery documents; `/` answers 404. There is no interface for people: every tool returns structured data validated against the qyl API contract, plus a short text rendering for the model.

## Install

One qyl plugin serves Claude Code and Codex. It connects the endpoint above and bundles the qyl skills.

Claude Code, from the [ancplua-anthropic](https://github.com/ANcpLua/ancplua-anthropic) marketplace:

```bash
claude plugin marketplace add ANcpLua/ancplua-anthropic
claude plugin install qyl@ancplua-anthropic
```

Codex, from the [ancplua-openai](https://github.com/ANcpLua/ancplua-openai) marketplace:

```bash
codex plugin marketplace add ANcpLua/ancplua-openai
codex plugin add qyl@ancplua-openai
```

ChatGPT: add `https://mcp.qyl.at/mcp` as a custom MCP server (connector) with OAuth and request `qyl:read qyl:write qyl:delete`. ChatGPT discovers the authorization server and runs the sign-in.

Any other MCP client: add the URL as a remote Streamable HTTP server with OAuth, for example `claude mcp add --transport http qyl https://mcp.qyl.at/mcp` and then `/mcp` to sign in.

Start a new session after installing. One call to `triage` without arguments proves the connection and the sign-in.

## Local stdio

```bash
npx qyl-mcp-server --stdio
```

The executable needs Bun 1.4 or newer on `PATH`. It reads the Collector at `QYL_COLLECTOR_URL`, by default the local one `qyl up` starts, with the credential in `QYL_API_KEY`; `QYL_PROJECT` selects a project. Over stdio there is no OAuth: the Collector key's explicit `read`, `write` and `delete` roles decide what the server may change. stdio serves the same tools and skills and no Events, and opens no network listener.

## Authorization

qyl is an OAuth 2.1 Resource Server. Auth0 at `https://qyl-eu.eu.auth0.com/` issues the tokens; clients use Authorization Code with PKCE for the exact resource `https://mcp.qyl.at/mcp`. `/.well-known/oauth-protected-resource/mcp` names the issuer and the scopes. Clients register through a Client ID Metadata Document or an OAuth client registered for them. The server checks the issuer, resource audience, expiry, RFC 9068 token profile, signature and scopes on every request; there is no anonymous access.

| Scope | Grants |
| --- | --- |
| `qyl:read` | Every request. The read tools need nothing more. |
| `qyl:write` | The tools that create or update annotations and saved queries and set failure status. |
| `qyl:delete` | `delete_record`, which removes one annotation or saved query. |

A write call whose token lacks the scope is answered `403` with an `insufficient_scope` challenge that names it. Reconnect qyl and approve that scope; some clients do not restart authorization on their own, so retrying the call alone may not help.

## Reading results

- **Window.** Time-filtered tools take absolute RFC 3339 `start_time` and `end_time`, or `lookback_minutes`: 60 by default, 7 days for `list_releases`, at most 30 days. Every result reports the `window` it used.
- **Filters and pages.** `matchers` select by attribute key with `eq`, `neq`, `in`, `prefix`, `contains`, `exists`, `gt`, `gte`, `lt` or `lte` before paging. `has_more` and `next_cursor` continue the same query in a stable order.
- **Coverage.** Read results state how much was examined, matched and returned, and whether the result was truncated. An empty result is not proof that an application is healthy, and `verify_fix` answers `pending` until enough traffic has passed.
- **Errors.** A failed call returns `isError` with `structuredContent.error`: a stable `code`, `retryable`, and the Collector's RFC 9457 [problem type](/problems/) as `problem_type` when it reported one. Collector failures stay errors, never empty data.
- **Writes.** Updates and deletes send the object's current `etag`; a stale one fails with `precondition_failed`. The create tools accept an `idempotency_key`.
- **Telemetry is data.** Text recorded by an application is returned as data and never treated as instructions.

## Skills

The server publishes its skills through the `io.modelcontextprotocol/skills` extension: `skills/list` and `skills/get` return the catalog, and every file of a skill is a `resources/read` under a `skill://` URI whose content matches the SHA-256 digest the catalog names. ## Events

`https://mcp.qyl.at/mcp` serves MCP Events to authenticated callers through `events/list`, `events/subscribe` and `events/unsubscribe`. The one event, `trace.error`, fires when a trace with at least one error span reaches the caller's Collector project; the optional `service_name` argument narrows it to one service. Clients that implement MCP Events, such as ChatGPT, subscribe with a webhook.

- **Delivery.** Each delivery carries `trace_id`, `root_span`, `services`, `span_count`, `duration_ms` and `start_time`, signed per Standard Webhooks with the subscriber's `whsec_` secret. The callback must be a public HTTPS address and pass a verification request first; redirects are not followed.
- **Lifetime.** A subscription lasts 60 minutes unless the client asks for between 5 minutes and 24 hours, and ends there unless refreshed. One caller holds at most 20.
- **No replay.** The server polls the Collector every 30 seconds while a subscription is live. The first poll sets the baseline; traces that arrive while the server is down are not delivered.
- **Access.** The subscriber's Auth0 account, grant and `qyl:read` permission are checked again before each delivery. Revoked access removes the subscription; an authorization outage suspends delivery.

Local stdio and unauthenticated local HTTP serve no Events.

## Troubleshooting

- **Sign-in fails:** confirm the client uses the exact `/mcp` resource, then reconnect and complete the authorization flow.
- **A permission is missing:** reconnect and approve the scope the challenge names. Contact [support](/support/) if sign-in cannot grant it.
- **No project is available:** your account has no Collector project yet; write to [support](/support/) with the client name and the approximate time, never credentials.
- **Results are empty:** check the window, service and filters, and confirm the application sends OTLP to the Collector project you read. See [getting started](/docs/getting-started/).
- **A write conflicts:** read the object again for its current `etag` before repeating the change.
