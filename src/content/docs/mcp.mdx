## Endpoint

The canonical hosted MCP resource is:

```text
https://mcp.qyl.at/mcp
```

The root `https://mcp.qyl.at/` is a product page, not a second protocol endpoint. `/healthz` is the platform health check.

## Add it from a client

For Claude Code:

```bash
claude mcp add --transport http qyl https://mcp.qyl.at/mcp
```

A compatible client discovers the protected-resource metadata, identifies itself through a client metadata document (CIMD) or dynamic registration (DCR), and opens Authorization Code with PKCE for the exact resource `https://mcp.qyl.at/mcp`. Hosted access requires `qyl:read` and an explicit Auth0 client grant; registering a client alone does not grant access.

For ChatGPT, add the same endpoint as an OAuth MCP connection and include `qyl:read` in its base scopes. Complete the qyl service login and consent. This is a custom connection; public directory submission is still in preparation.

## Authentication boundary

qyl acts only as an OAuth 2.1 Resource Server. Auth0 at `https://qyl-eu.eu.auth0.com/` owns authorization and token issuance. The qyl server verifies:

- the exact issuer;
- the exact resource audience;
- the `qyl:read` scope;
- expiry and the RFC 9068 access-token profile;
- the token signature through the issuer’s JWKS.

There is no proprietary static bearer-token path and no embedded anonymous authorization server.

## Local alternative

For a same-machine client, run the published server over stdio:

```bash
npx -y qyl-mcp-server --stdio
```

The stdio server exposes the same Qyl read tools and MCP Apps without creating an Internet-facing listener.

Both transports use SDK v2 to serve `2026-07-28` and supported 2025-era tool clients. The workbench explicitly enables `versionNegotiation: { mode: "auto" }`; the SDK Client's own default remains the 2025 handshake. See [protocol support](/docs/protocol-2026-07-28/).

## Optional ChatGPT Events

On a supported ChatGPT connection using `2026-07-28`, `trace.error` subscriptions can report matching errors, optionally filtered by service. Enabling the feature does not subscribe anyone automatically. Ordinary read tools remain available to clients without Events support.

An operator enables Events by configuring `MCP_EVENTS_STORE` on an authenticated deployment with persistent storage and the access checker described in the [server configuration](https://github.com/ANcpLua/qyl.mcp#mcp-events). The store retains subscription owner/client identifiers, callback and filter settings, signing keys, and expiry. It does not retain subscribers' OAuth access or refresh tokens or copy the collector's telemetry. Expiration, revoked access, or unsubscribe removes the subscription and stops delivery.
