[Qyl.Telemetry.Tests](https://github.com/ANcpLua/Qyl.Telemetry.Tests) is the active repository for shared telemetry support and the unit, integration and end-to-end suites. It combines the retained receiver and architecture code. Its shared project is source support, not a newly published NuGet package.

The former receiver and architecture-prototype repositories are archived. Existing consumers can continue using the published receiver package documented below.

## Existing receiver package

`Qyl.Telemetry.Testing` captures what an application exports over OTLP/HTTP protobuf and OTLP/gRPC, including gzip. The last released package is **{versionOf("Qyl.Telemetry.Testing")}**. It targets .NET 10; its MSTest integration uses the official framework and runner.

```bash
dotnet add package Qyl.Telemetry.Testing
```

Start an owned `OtlpReceiver` through `OtlpReceiver.StartAsync()`, configure the application's exporters, exercise the real application, and await the evidence your test requires. HTTP uses `receiver.Endpoint` plus `v1/traces`, `v1/logs` or `v1/metrics`; gRPC uses `receiver.GrpcEndpoint` without a signal path. `AwaitAsync` has a bounded deadline and preserves caller cancellation. Stop and flush producers before disposing the receiver.

Both transports default to **16 MiB**. Override the positive `maxPayloadBytes` argument at startup, or pass it to
`QylTest.TraceAsync`:

```csharp
await using var receiver = await OtlpReceiver.StartAsync(
    maxPayloadBytes: 4 * 1024 * 1024,
    cancellationToken: TestContext.CancellationToken);
```

Select 4 MiB when matching the production Collector's default gRPC limit. HTTP bounds encoded and decompressed bytes
independently, including chunked gzip. gRPC bounds each message and its decompressed output. Overflow returns HTTP 413
with an OTLP Status or gRPC `ResourceExhausted`; malformed protobuf returns HTTP 400 or gRPC `InvalidArgument`.
Diagnostics report the configured byte limit. The testing receiver accepts protobuf, not OTLP JSON.

The capture includes traces, logs and all five metric shapes, with typed values, resource and scope metadata, span events, links and exemplars. `Snapshot().Requests` retains original protobuf payloads before decoding, including rejected records and unknown fields. Export receipts retain diagnostics. Diagnostic JSON includes the complete metric shape and points.

`QylTrace` selects a trace without deleting the full capture. Its service-call graph uses unique span identities, so retransmitting an export does not invent another call. Database identity includes system, server and namespace.

Metrics usually describe a process or aggregation window. Attribute them to an invocation only through an explicit resource partition or matching exemplar. Seeing a metric near a request is not correlation.

`RegistryConformance.Check(capture)` checks observed attribute types and registered metric units. Custom application names remain valid; deprecated conventions remain visible. An empty capture cannot pass conformance. The audit does not invent required attributes or infer the originating SDK instrument from an exported aggregation.

The optional `[QylTelemetry]` integration delegates to the original MSTest method attribute. The consuming test assembly owns the documented global initialize and cleanup hooks. Discovery locations, data-row identity, duration and original failures remain the runner's responsibility.

See the [archived package source and executable examples](https://github.com/ANcpLua/Qyl.Telemetry.Testing) and the [MSTest 4.5.1 living reference](https://github.com/ANcpLua/mstest-samples-with-docs-4.5.1). Capturing an export proves its wire content; query the collector separately when the assertion concerns persistence.
