## Start the workbench

The workbench lives in the separate `qyl.mcp` repository. Bun 1.4 is the runtime
and the only package manager there — one `bun.lock`, no npm install path — and
the repository runs on Node.js 24.

```bash
git clone https://github.com/ANcpLua/qyl.mcp.git
cd qyl.mcp
bun install --frozen-lockfile
bun run build
bun run start:workbench
```

Open `http://127.0.0.1:18888`. The browser, runner API, and managed child processes run with the local user’s permissions, so the runner binds only to loopback.

## Add a server

User-created connections support:

- **Streamable HTTP** with a credential-free endpoint plus header references to environment variables.
- **stdio** with an executable, one argument per line, an optional working directory, and environment-variable mappings.

Only environment-variable names reach the browser or durable state. The runner resolves their values at connection time and registers them with the shared redactor.

The workbench explicitly sets `versionNegotiation: { mode: "auto" }`. It attempts `2026-07-28` and can negotiate a supported 2025-era server through the SDK's compatibility path. The connection records the revision actually negotiated; see [protocol support](/docs/protocol-2026-07-28/).

## Review before execution

MCP annotations are safety hints, not authorization. A tool runs without confirmation only when it is explicitly read-only, non-destructive, and closed-world. Missing, contradictory, mutating, destructive, or open-world hints require approval of the exact call.

qyl's own write tools never meet that rule. `create_annotation` and `create_saved_query` declare `readOnlyHint: false` and count as mutating; `update_annotation`, `update_saved_query` and `delete` declare `destructiveHint: true` and count as potentially destructive. Every call to them therefore waits for approval of its exact arguments, and the execution record keeps that confirmation. `list_saved_queries` and `run_saved_query` are explicitly read-only, non-destructive, and closed-world, so they run without confirmation like the other read tools.

## Keep the evidence

Every persisted execution includes its request, result or typed error, lifecycle,
duration, retries, cancellation, and correlated qyl evidence. The live protocol
journal is metadata-only by default; redacted, bounded JSON-RPC bodies require
`QYL_MCP_CAPTURE_CONTENT=1`. Tests and suites invoke real tools and retain their
assertions. Completed runs can be compared and exported as contract-validated JSON
or Markdown.

Workbench state defaults to `~/.qyl/mcp-workbench.json` and uses atomic replacement with private filesystem modes.
