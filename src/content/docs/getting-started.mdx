## Run the Collector

qyl ships as a .NET tool. The package contains the NativeAOT Collector for your runtime identifier; it needs no repository clone and no Node.js.

```bash
dotnet tool install --global qyl
qyl up
```

`qyl up` binds these loopback ports and fails up front if one is already taken:

| Port | Purpose |
| --- | --- |
| `4317` | OTLP/gRPC receiver |
| `4318` | OTLP/HTTP receiver |
| `5100` | Collector API: reads, analysis, annotations and saved queries |
| `5200` | Isolated diagnostics collector |
| `18889` | qyl runner API |

Telemetry is stored under `~/.qyl/`, never in the working directory. There is no web interface: agents read the Collector through MCP, and programs through its API.

## Send telemetry from any OpenTelemetry SDK

Nothing about the Collector is language specific. Any compliant OTLP exporter (Python, Go, Java, Node.js, Rust, .NET) reaches it through the standard environment variables:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4318
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
```

## Connect an agent

Run the MCP server over stdio next to the local Collector. It needs Bun 1.4 or newer on `PATH`:

```bash
npx qyl-mcp-server --stdio
```

Add that command to the agent's MCP configuration, for example `claude mcp add qyl -- npx qyl-mcp-server --stdio` in Claude Code. Then ask the agent about the run. The `qyl-investigate` skill, served with the tools, starts an investigation with `triage`. The hosted endpoint, the plugin for Claude Code and Codex, and the ChatGPT connector are described in [Connect an agent](/docs/mcp/).

## The .NET fast path

A .NET host needs no environment variables. Add the instrumentation package:

```bash
dotnet add package Qyl.Telemetry.Hosting
```

The package changes nothing on its own. `AddQyl()` is the activation line, and it belongs in application setup:

```csharp
builder.AddQyl();
```

That call discovers a local `qyl up` Collector, applies the supported compile-time instrumentation, copies `session.id` from a span to every descendant span in the same process, and exports through the OpenTelemetry SDK. Standard `OTEL_*` settings still take precedence, so the fast path and the generic path never disagree.

## What is retained

The Collector stores traces, logs and metrics in DuckDB, plus the annotations, saved queries and failure status agents create. Telemetry is kept for 30 days by default (`QYL_RETENTION_DAYS`). Profiles are not supported.

## Stop cleanly

Press `Ctrl-C` in the terminal running `qyl up`. The host owns its child processes and shuts down the Collector and the diagnostics collector together.
