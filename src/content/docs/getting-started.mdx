## What starts locally

qyl ships as a .NET tool. The package contains the native collector and embedded dashboard for your current runtime identifier; it does not clone a repository or require Node.js.

```bash
dotnet tool install --global qyl
qyl up
```

Open `http://127.0.0.1:5100`. The fixed local surface is:

| Port | Purpose |
| --- | --- |
| `5100` | Product API and embedded dashboard |
| `4317` | OTLP/gRPC receiver |
| `4318` | OTLP/HTTP receiver |
| `5200` | Isolated diagnostics collector |
| `18889` | qyl host resource API |

The separate MCP workbench owns loopback port `18888`.

## Hello world from any OpenTelemetry SDK

Nothing about the collector is language specific. Any compliant OTLP exporter — Python, Go, Java, Node.js, Rust, .NET — reaches it through the two standard environment variables:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4318
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
```

Run the application, then connect an MCP client and ask your agent about the run rather than reading a dashboard yourself:

```bash
npx -y qyl-mcp-server --stdio
```

Three steps: `qyl up`, point `OTEL_EXPORTER_OTLP_ENDPOINT` at it, ask your agent.

## The .NET fast path

For a .NET host there is a shorter route that needs no environment variables. Add the instrumentation package:

```bash
dotnet add package Qyl.Telemetry.Hosting
```

The package changes nothing on its own. `AddQyl()` is the activation line, and it belongs in application setup:

```csharp
builder.AddQyl();
```

That call discovers a local `qyl up` collector, applies the supported compile-time instrumentation, copies `session.id` from a span to every descendant span in the same process, and exports through the OpenTelemetry SDK. Standard `OTEL_*` settings still take precedence, so the fast path and the generic path never disagree.

## Build an API on the same stack

`Qyl.Api.Sdk` is an MSBuild SDK for a Native AOT ASP.NET Core API. One line registers validation, problem details, the OpenAPI document and the telemetry above; see [API SDK](/docs/api-sdk/).

```xml
<Project Sdk="Qyl.Api.Sdk/5.0.0">
```

## What is retained

qyl stores traces, logs and metrics. Profiles are not supported.

## Stop cleanly

Press `Ctrl-C` in the terminal running `qyl up`. The host owns its child processes and shuts down the product collector, dashboard, and diagnostics collector together.
