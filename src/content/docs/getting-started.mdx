## Run the Collector

qyl ships as a .NET tool. Its package for your platform carries the Collector, which `qyl up` runs on the .NET 10 runtime with ASP.NET Core; the .NET 10 SDK that installs the tool brings both. It needs no repository clone and no Node.js. (The hosted Collector at `api.qyl.at` is the same Collector, built with NativeAOT into a container.)

```bash
dotnet tool install --global qyl
qyl up
```

`qyl up` binds these loopback ports and fails up front if one is already taken:

| Port | Purpose |
| --- | --- |
| `4317` | OTLP/gRPC receiver |
| `4318` | OTLP/HTTP receiver |
| `5100` | Collector API: reads, analysis, annotations and saved queries |
| `5200` | Isolated diagnostics collector |
| `18889` | qyl runner API |

Telemetry is stored under `~/.qyl/`, never in the working directory. There is no web interface: agents read the Collector through MCP, and programs through its API.

## Send telemetry from any OpenTelemetry SDK

Nothing about the Collector is language specific. Any compliant OTLP exporter (Python, Go, Java, Node.js, Rust, .NET) reaches it through the standard environment variables:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4318
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
```

## Connect an agent

Run the MCP server over stdio next to the local Collector. It needs Bun 1.4 or newer on `PATH`:

```bash
npx qyl-mcp-server --stdio
```

Add that command to the agent's MCP configuration, for example `claude mcp add qyl -- npx qyl-mcp-server --stdio` in Claude Code. Then ask the agent about the run. The `qyl-investigate` skill, served with the tools, starts an investigation with `triage`. [Connect an agent](/docs/mcp/) covers every host: Claude, Claude Code, ChatGPT, Codex, the Claude and OpenAI APIs, and the hosted endpoint.

## The .NET fast path

A .NET host needs no environment variables. Add the instrumentation package:

```bash
dotnet add package Qyl.Telemetry.Hosting
```

Referencing the package compiles its instrumentation into the application; nothing is recorded or exported until `AddQyl()` runs. That call is the activation line, and it belongs in application setup:

```csharp
builder.AddQyl();
```

That call starts the compiled instrumentation, copies `session.id` from a span to every descendant span in the same process that has none, and exports through the OpenTelemetry SDK. It discovers a local `qyl up` Collector unless `OTEL_EXPORTER_OTLP_ENDPOINT`, `QYL_ENDPOINT` or an explicit collector endpoint in its options names one; `OTEL_SERVICE_NAME` still names the service.

## What is retained

The Collector stores traces, logs and metrics in DuckDB, plus the annotations, saved queries and failure status agents create. Telemetry is kept for 30 days by default (`QYL_RETENTION_DAYS`). Profiles are not supported.

## Stop cleanly

Press `Ctrl-C` in the terminal running `qyl up`. The host owns its child processes and shuts down the Collector and the diagnostics collector together.
